1. FUNÇÃO extractApiError DUPLICADA → UTILITÁRIO COMPARTILHADO
----------------------------------------------------------------------
Antes:
  A função extractApiError estava copiada idênticamente em 3 lugares:
  - src/pages/LoginPage.tsx (22 linhas)
  - src/pages/SignUpPage.tsx (22 linhas)
  - src/hooks/useAdmin.ts   (18 linhas, com nome extractErrorMessage)

  Qualquer ajuste na lógica de extração de erro precisava ser replicado
  manualmente nos 3 arquivos.

Depois:
  Criado src/lib/extractError.ts com a função:
    extractApiError(err: unknown): string

  Os 3 arquivos agora importam a função do mesmo lugar, sem duplicação.

Princípios:
  • DRY (Don't Repeat Yourself) — a lógica existe em um único local
  • Single Source of Truth — qualquer mudança na extração de erros
    é feita em um único arquivo
  • Nome consistente — antes havia extractApiError e extractErrorMessage
    para a mesma coisa; agora só extractApiError

Arquivos:
  src/lib/extractError.ts          (CRIADO)
  src/pages/LoginPage.tsx          (MODIFICADO — removeu código duplicado)
  src/pages/SignUpPage.tsx         (MODIFICADO — removeu código duplicado)
  src/hooks/useAdmin.ts            (MODIFICADO — trocou extractErrorMessage
                                    por extractApiError)

----------------------------------------------------------------------
2. DOWNLOAD DE CSV/XLSX DUPLICADO → HELPER EXTRAÍDO
----------------------------------------------------------------------
Antes:
  No EquipmentImportExport, os callbacks onSuccess do CSV e do XLSX
  continham o mesmo bloco de 5 linhas para fazer download via
  URL.createObjectURL / document.createElement('a') / revoke.

  Código duplicado:
    onSuccess: (blob) => {
      const url = URL.createObjectURL(blob);
      const a = document.createElement('a');
      a.href = url;
      a.download = 'equipamentos.csv';  // só mudava o nome
      a.click();
      URL.revokeObjectURL(url);
    },

Depois:
  Criadas duas funções em src/lib/extractError.ts:
    downloadCsv(blob: Blob): void
    downloadXlsx(blob: Blob): void

  O componente agora passa apenas a função (onSuccess: downloadCsv).

Princípios:
  • DRY — o padrão de download existe uma vez
  • Nome intencional — downloadCsv e downloadXlsx comunicam
    exatamente o que fazem
  • Responsabilidade única — a lógica de download não pertence
    ao componente de UI

Arquivos:
  src/lib/extractError.ts                   (MODIFICADO — add download helpers)
  src/components/equipments/EquipmentImportExport.tsx (MODIFICADO)

----------------------------------------------------------------------
3. STALE COMMENTS REMOVIDOS DO INTERCEPTOR api.ts
----------------------------------------------------------------------
Antes:
  O response interceptor continha comentários de desenvolvimento:
    // ✅ NOVO: Ignora refresh automático em rotas públicas de auth
    // ❌ se não for caso de retry → só rejeita
    // ✅ Agora rejeita com o erro ORIGINAL do login
    // ... resto do código de refresh (mantém igual)

  Esses comentários eram resquícios de revisões anteriores, sem
  valor para manutenção futura.

Depois:
  Comentários removidos. O código ficou mais limpo e legível.

Princípios:
  • Comentários explicam o "porquê", não o "o quê" — o código já
    comunica a intenção (variáveis is401, isRefreshRoute, etc.)
  • Código limpo — comentários obsoletos são ruído

Arquivos:
  src/lib/api.ts (MODIFICADO)

----------------------------------------------------------------------
4. ConfirmDelete: ESTILO INLINE SUBSTITUÍDO POR btn-danger
----------------------------------------------------------------------
Antes:
  O botão de exclusão usava classes Tailwind inline:
    bg-red-600 hover:bg-red-700 focus:ring-red-500

  Isso duplicava o que já existia no CSS global como classe .btn-danger,
  gerando inconsistência visual (outros botões de exclusão usavam
  btn-danger, este não).

Depois:
  Substituído por className="btn-danger", consistente com o resto
  do sistema.

Princípios:
  • Consistência — todos os botões de exclusão usam a mesma classe
  • Manutenibilidade — para alterar o estilo de exclusão, muda-se
    o CSS global, não cada botão individualmente
  • Reuso — respeita o design system existente

Arquivos:
  src/components/admin/ConfirmDelete.tsx (MODIFICADO)

----------------------------------------------------------------------
5. useAdmin: CONSTANTES NOMEADAS NO LUGAR DE MAGIC NUMBERS
----------------------------------------------------------------------
Antes:
  O hook usava números literais sem nome:
    const LIMIT = 10;                         // sem contexto
    limit: 100                                // sem explicação

  O número 10 como limite de página não era consistente com o
  backend que foi alterado para 50.

Depois:
  As constantes foram nomeadas:
    const USERS_PAGE_LIMIT = 50;              // alinhado com backend
    const MAX_ADMINS_TO_FETCH = 100;          // explica o propósito

  Agora é fácil ajustar os limites e entender o que cada um significa.

Princípios:
  • Nome intencional — a constante revela o propósito do valor
  • Manutenibilidade — altera-se o valor em um único lugar
  • Sem magic numbers — nenhum número literal sem explicação

Arquivos:
  src/hooks/useAdmin.ts (MODIFICADO)
